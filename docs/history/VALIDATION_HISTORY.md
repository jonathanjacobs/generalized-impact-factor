## 2026-09-22 — Full end-to-end run completed; correction to the entry above

- **Correction:** the entry above attributed the `HTTP 400: Bad Request` failures to "NCBI-side throttling on the shared `NCBI_API_KEY`." That diagnosis was wrong. A direct, raw HTTP call to NCBI's `esearch.fcgi` with that API key returned the JSON body `{"error":"API key status invalid","api-key":"a9daa1fd...c509","type":"api-key","status":"invalid"}` — the key itself is invalid (expired or revoked), not rate-limited. The same query succeeds immediately when the API key is omitted (falls back to the unauthenticated 3 requests/second limit). Anyone else on this host relying on `NCBI_API_KEY` for other tools should check or rotate it.
- **Code or workflow version:** commit `4d2a8a2` (post library-split, includes `docs/README.md`).
- **Settings, input, and reference identifiers:** term `ATCC CRL-1585`; `--window_length_years 3`, `--retmax 10`; live NCBI E-utilities and NIH iCite APIs; run with `NCBI_API_KEY` explicitly unset (`env -u NCBI_API_KEY`) to work around the invalid key above.
- **Environment and checks performed:** ran on the `an internal ATCC HPC host` host, Python 3.9.19. Ran the full CLI pipeline (`impact_lookup.py`) end-to-end: PMC search → PMC-to-PMID conversion → `terms_citations.tsv` → iCite citation counts → `terms_metrics.tsv`. Independently re-fetched citation counts for the resulting 6 PMIDs directly from the iCite API and hand-computed H/G/i10 from them.
- **Observed result:** `terms_metrics.tsv` reported `Total Mentions=6, H-index=3, G-index=6, i10-index=2` for `ATCC CRL-1585`. `terms_citations.tsv` had 6 well-formed rows (Term, PubMedID, Year, Title, Journal, AuthorList, Institution), with titlecasing correctly preserving alphanumeric/acronym tokens (e.g. "SARS-CoV-2", "HTRA1", "ERBB"). The independently-fetched citation counts for the 6 PMIDs, sorted descending, were `14, 12, 6, 3, 2, 1`; hand-computing H/G/i10 from those counts gives exactly `(3, 6, 2)`, matching the tool's output. This satisfies R2 (no missing rows — confirmed separately in the prior entry) and directly confirms the full pipeline, including the previously-uncovered `dump_term_citations_tsv` and `get_citation_counts_icite`, produces correct output against live data.
- **Limitations and skipped or inconclusive checks:** only one term was checked end-to-end; R3 (no double-counted PMIDs) and R5 (fuzzy-matching false-positive/false-negative rate) are still unchecked — see `docs/REQUIREMENTS.md` and `docs/TESTING.md`. This run used a working environment (API key unset) rather than the host's actual default configuration (which currently fails); the invalid `NCBI_API_KEY` itself is an environment problem outside this project's code, not something this project can fix.
- **Evidence location:** this entry. The run itself used scratch files outside the repository (per `docs/DATA_GOVERNANCE.md`, run outputs are not committed) and is reproducible by running `impact_lookup.py` with a working NCBI environment.
- **Reviewer and decision:** not yet reviewed by a person other than the person who ran it. Recommend Jonathan Jacobs (Project Lead / Technical Lead) spot-check the citation counts above against PubMed/iCite directly before relying on this as full validation.
